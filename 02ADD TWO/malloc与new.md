# malloc 与 new 的拆解

> 由 `struct ListNode *dummy = (struct ListNode *)malloc(sizeof(struct ListNode));`
> 一行代码引发的对比笔记。只会 C++ 的话，`new` 一行就完事了，但 C 里这行藏着不少东西。

---

## 一、这一行拆成五块

```c
struct ListNode *dummy = (struct ListNode *)malloc(sizeof(struct ListNode));
//     ① 指针变量     =      ③ 类型转换 ② 分配内存  ④ 计算字节数
```

### ④ `sizeof(struct ListNode)` —— 编译期运算符

返回这个结构体占几个字节，不运行就知道。64 位下 `int val`（4 字节）+ 指针（8 字节）+ 对齐填充，一般是 **16 字节**。

### ② `malloc(16)` —— 向堆申请内存

`malloc` 来自 `<stdlib.h>`，干的事就是："给我 16 字节连续内存"，它返回这块内存的起始地址。注意两点：

- 它只**圈地**，不清地 —— 这块内存里的值是**垃圾数据**（上一个程序留下的残骸）
- 失败时返回 `NULL`（比如内存不够）

### ③ `(struct ListNode *)` —— 类型转换

`malloc` 的返回类型是 `void *`（无类型指针，C 的"万金油指针"）。必须告诉编译器"这块地我当 `struct ListNode` 用"，于是强转成 `struct ListNode *`。

> 小知识：在纯 C 里这个转换其实是**可省略**的（`void *` 会自动转成任意指针），写出来纯粹是表达意图、顺手兼容 C++；但在 C++ 里**必须写**，不写编译报错。

### ① `struct ListNode *dummy` —— 声明一个指针变量

这里要分清**两样东西**：

| 东西 | 在哪 | 是什么 |
|---|---|---|
| `dummy` 这个指针变量 | **栈**上 | 存一个地址，目前是垃圾值 |
| `malloc` 分配的那 16 字节 | **堆**上 | 是真正存放节点数据的"家" |

### ⑤ `=` —— 把堆地址塞进指针

赋值之后 `dummy` 才"指"向那块内存，之前它是个悬空的野指针。

---

## 二、对比 C++ 的 `new`

```cpp
struct ListNode *dummy = new ListNode();   // C++ 一行搞定
```

`new` 之所以简单，是因为它**一次干了两件事**，而 `malloc` 只干一件：

| | `new` | `malloc` |
|---|---|---|
| 分配内存 | ✅ | ✅ |
| 构造（清零/调构造函数） | ✅ **自动** | ❌ 内存是垃圾值 |
| 返回类型 | 直接是 `ListNode *` | `void *`，要强转 |
| 失败处理 | 抛异常 `std::bad_alloc` | 返回 `NULL` |
| 配套释放 | `delete` | `free` |

所以 C++ 里 `new ListNode()` 隐含了"分配 + 构造"，而且不需要强转、失败会抛异常——这就是感觉它"简单"的原因，它把 C 里要手动做的两件事打包了。

对应地，C 里写 `node->val = 7; node->next = NULL;` 其实就是**手动做构造函数**——因为 `malloc` 出来的内存是垃圾值，必须自己把 `val` 和 `next` 填好，不然 `next` 是个野指针，遍历直接崩。

---

## 三、释放也要配套

| C | C++ |
|---|---|
| `free(p);` | `delete p;` |
| `free` 只还内存，不调析构 | `delete` 先调析构函数，再还内存 |

而且 C 里 `malloc` 了几次，就要 `free` 几次；C++ 里 `new` 了就要 `delete`。混用（`malloc` 配 `delete`、`new` 配 `free`）是未定义行为，别干。

---

## 四、一句话总结

> `malloc` = 只圈地不清地；`new` = 圈地 + 装修好再给你钥匙。
> 所以 C 里 `malloc` 之后必须手动"装修"（初始化字段），并且记得 `free` 还地。

---

## 五、C 与 C++：方便 vs 控制感

### 为什么 C++ 这么"方便快捷"？

先纠正一个错觉：C++ **不是运行更快**，只是**开发更省心**。`new` 的方便来自一个机制：

> C++ 有**构造函数/析构函数**。`new` 不只是圈地，它会在那块地上**自动调用构造函数**把对象初始化好；`delete` 也会自动调析构函数善后。

而 C 的 `malloc` 不会（也没有"构造函数"这个概念），所以必须自己手动初始化。方便 = 编译器帮你把"装修"这件事打包了，代价是**中间隔着几层抽象**，对内存的直觉不如 C 那么直接。

真要比速度，C 在某些场景反而更快（没有虚函数、没有 RAII 的隐式清理逻辑、编译器优化更直白）。C++ 的"快"是**开发快**，不是**运行快**。

### 控制感去哪了？—— 其实没丢

**C++ 是 C 的超集，在 C++ 里照样能写 `malloc` / `free`**，一个字节都不少。"手动 malloc 控制感更强"这个直觉完全对，而且 C++ 不但保留了它，还额外给了几把更精细的钥匙：

| 武器 | 作用 |
|---|---|
| `malloc` / `free` | 和 C 完全一样的原始分配 |
| `placement new` | **在已分配的内存上**构造对象（不重新分配，位置自己定） |
| `operator new` / `operator delete` | 重载全局的分配行为，接管所有 `new` |
| 自定义 Allocator | 让 `vector`、`map` 等容器用你自己的内存池 |

也就是说：C++ 不是"没有控制感"，而是**默认给你省心的 `new`，把精细的钥匙也留给你**。为什么默认用 `new` 而不是 `malloc`？因为 **RAII**（资源获取即初始化）——对象销毁时析构函数自动跑，内存不会漏。C 里忘了 `free` 就泄漏了，`new` 配合析构帮你兜底。

> 一句话：**C 逼你控制，C++ 允许你控制但默认帮你控制。**控制感 C 更强，但"失控"的风险 C 也更大。
