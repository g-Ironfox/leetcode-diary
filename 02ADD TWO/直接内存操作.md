# 内存随意操作：指针就是地址

> 由"C 能不能更进一步操作内存？比如随意读取内存？"引发的笔记。
> `malloc` 只是冰山一角；往下还有指针算术、地址强转、字节级搬运。
> 而"随意读内存"能不能真跑起来，取决于**有没有操作系统**。

---

## 一、C 里能对内存做的"更进一步"操作

C 里**指针就是地址**，你可以拿到几乎任何东西的地址，甚至直接对着地址读写：

```c
// 1. 任意地址读写（假设这个地址合法可访问）
*(int *)0x12345678 = 42;        // 往地址 0x12345678 写一个 int
int x = *(int *)0x12345678;     // 从该地址读一个 int

// 2. 字节级搬运（string.h 三件套）
memset(buf, 0, 100);           // 把 100 字节全清零
memcpy(dst, src, 100);         // 拷贝 100 字节
memmove(dst, src, 100);        // 拷贝（允许重叠区域）

// 3. 类型双关：把同一块内存"换个视角"看
float f = 3.14f;
unsigned int bits = *(unsigned int *)&f;   // 读出 float 的原始位模式
```

但这些操作**能不能真跑起来，取决于你身处哪个世界**。

---

## 二、世界 A：有操作系统（LeetCode 所在的世界）

程序跑在**虚拟内存**里，CPU 有个叫 **MMU**（内存管理单元）的硬件在做地址翻译和权限检查。操作系统给你画的"内存地图"和物理内存根本不是一回事。这时候"随意读任意地址"的结果是：

```c
*(int *)0x12345678 = 42;   // 💥 Segmentation fault（段错误）
```

读的是一个**虚拟地址**，那一片在进程的地址空间里可能是空的、是只读的、或干脆不属于你，MMU 立刻拦截，内核发 `SIGSEGV`，程序崩。这其实是个**安全特性**——不然任何程序都能偷看别的进程的内存了。

---

## 三、世界 B：无操作系统（裸机 / 嵌入式 / 内核）

没有 MMU 帮你挡，**指针就是物理地址**，`*(int *)0x12345678 = 42` 是真的往物理内存 0x12345678 写。这就是嵌入式程序员天天干的事：

```c
// 读写硬件寄存器（memory-mapped I/O）
#define GPIO_BASE 0x40021000
*(volatile unsigned int *)(GPIO_BASE + 0x04) |= (1 << 5);   // 点亮一个 LED
```

硬件寄存器被映射到固定的内存地址上，读那个地址 = 读传感器状态，写那个地址 = 命令外设干活。**这是 C 独步天下的领域**——C++ 也能做，但 C 的哲学"信任程序员、不设防"让它成为嵌入式/操作系统的主流语言。

---

## 四、总结

| | 世界 A（有 OS） | 世界 B（裸机/内核） |
|---|---|---|
| 指针指向 | 虚拟地址 | 物理地址 |
| 任意地址读写 | ❌ 段错误，被 MMU 拦 | ✅ 随便读，还能碰硬件寄存器 |
| LeetCode 刷题 | ✅（只能用合法内存） | — |

> 一句话：**"随意读内存"在操作系统里是被 MMU 拦住的安全特性；只有在裸机上，指针才能随心所欲、直接摸到硬件。**
