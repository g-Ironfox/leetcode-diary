# Hash 查重与复杂度降阶

## 一、为什么查重方式会影响复杂度的幂

很多算法都包含这样的操作：

> 当前元素以前是否出现过？如果出现过，它上次在哪里？

如果每次都从已有元素中线性搜索，单次查重需要 $O(n)$。如果外层过程本身还要执行 $O(n)$ 次，总时间就是：

$$
O(n)\times O(n)=O(n^2)
$$

使用 hash 表或固定字符表后，查询可以降为平均 $O(1)$；在本题的 ASCII 数组直接寻址中，查询就是确定的 $O(1)$。于是：

$$
O(n)\times O(1)=O(n)
$$

这不是只优化了一个常数，而是消掉了一个随输入规模增长的 $O(n)$ 因子。因此复杂度从平方级降到线性级，也就是常说的“降了一阶”或“降低了复杂度的幂”。

## 二、线性查重和 Hash 查重

### 线性查重

```c
int duplicate = 0;
for (int k = left; k < right; k++) {
    if (s[k] == s[right]) {
        duplicate = 1;
        break;
    }
}
```

窗口长度最坏为 $n$，所以一次查重最坏为 $O(n)$。

### 使用 `seen[]` 查重

```c
unsigned char current = (unsigned char)s[right];
if (seen[current]) {
    /* current 已经出现 */
}
seen[current] = 1;
```

字符值直接作为数组下标，不需要扫描已有字符，一次查询和写入都是 $O(1)$。

### 使用 `last[]` 定位重复位置

```c
if (last[current] >= left) {
    left = last[current] + 1;
}
last[current] = right;
```

`seen[]` 只能回答“出现过没有”，`last[]` 还能回答“上次出现在哪里”。因此 `last[]` 不仅完成查重，还能让左边界直接跳过冲突位置。

## 三、本题三个层次的降阶

### 1. 纯暴力：$O(n^3)$

`4_bruteforce.c` 包含三层工作：

1. 枚举左端点 `left`；
2. 从该左端点向右扩展 `right`；
3. 用 `k` 扫描窗口来检查 `s[right]` 是否重复。

最坏情况下：

$$
O(n)\times O(n)\times O(n)=O(n^3)
$$

### 2. 暴力枚举 + Hash：$O(n^2)$

`3_bruteforce_hash.c` 用 `seen[]` 把第三层线性查重替换为 $O(1)$：

$$
O(n)\times O(n)\times O(1)=O(n^2)
$$

这说明 Hash 成功消掉了一个 $O(n)$ 因子。但是每次改变 `left` 后，`right` 仍然重新扫描，所以还有两层规模为 $n$ 的工作。

### 3. 滑动窗口 + `last[]`：$O(n)$

`2_sliding_window_hash.c` 进一步让 `right` 只向右移动一次，并用 `last[]` 在 $O(1)$ 时间定位冲突字符：

$$
O(n)\times O(1)=O(n)
$$

完整的优化过程是：

$$
O(n^3)\xrightarrow{\text{Hash 查重}}O(n^2)
\xrightarrow{\text{避免右边界重新扫描}}O(n)
$$

## 四、为什么 `1_sliding_window_no_hash.c` 仍然是 $O(n^2)$

`1_sliding_window_no_hash.c` 已经做到 `end` 不回退，外层扫描只有 $O(n)$。但每轮都要使用 `temp` 线性扫描当前窗口：

$$
O(n)\text{ 个 end 状态}\times O(n)\text{ 的 temp 查重}=O(n^2)
$$

把 `temp` 替换为 `last[]` 后，单次查重和定位从 $O(n)$ 变为 $O(1)$，整体才从 $O(n^2)$ 降到 $O(n)$。

这也说明：右指针不回退是线性滑动窗口的重要条件，但不是充分条件。还必须保证维护窗口的额外工作总计不超过 $O(n)$。

## 五、Hash 不会自动让所有算法变成 $O(n)$

分析复杂度时，应先拆出各项成本：

$$
\text{总时间}=\text{状态或候选数量}\times\text{处理一个候选的成本}
$$

Hash 只能优化它实际替代的那部分。

例如暴力枚举所有左端点和右端点时，候选窗口已有 $O(n^2)$ 个。即使把每个窗口的查重降到 $O(1)$，整体仍至少需要处理这 $O(n^2)$ 个候选，不会自动变成 $O(n)$。

判断 Hash 能否降阶，可以依次问：

1. 当前是否存在“为了找一个值而线性扫描”的步骤？
2. Hash 能否保存这个步骤所需的历史信息？
3. 该线性扫描是否位于一个执行 $O(n)$ 次的外层过程中？
4. 替换后是否还存在其他独立的 $O(n)$ 重复扫描？

如果前三个答案是“是”，Hash 通常能消掉一个 $O(n)$ 因子；如果第四个答案也是“是”，整体可能只降一阶，而不会直接降到 $O(n)$。

## 六、数组直接寻址和普通 Hash 表的区别

本题字符范围固定，可以使用：

```c
int seen[256] = {0};
int last[256];
```

字符的数值直接作为下标：

$$
h(c)=c
$$

这是**直接寻址表**。它没有哈希冲突，访问最坏也是 $O(1)$。口语上经常把它称为“Hash 数组”，但准确说法是固定键空间上的直接寻址。

普通 Hash 表则需要哈希函数和冲突处理：

- 平均查询、插入为 $O(1)$；
- 极端冲突情况下最坏可能退化为 $O(n)$；
- 通常需要比实际元素更多的空间来控制装载因子。

因此，写复杂度时应区分：

- `seen[256]`、`last[256]`：确定的 $O(1)$ 直接寻址；
- 通用 Hash 表：通常按平均 $O(1)$ 分析。

## 七、空间换时间为什么值得

使用 `last[256]` 会增加固定大小的辅助空间，但输入越长，这个数组仍然只有 256 个元素，所以在固定字符集下：

$$
\text{空间复杂度}=O(1)
$$

它换来的时间差距却会随 $n$ 快速扩大。忽略常数时：

| $n$ | $n$ | $n^2$ | $n^3$ |
| ---: | ---: | ---: | ---: |
| 100 | 100 | 10,000 | 1,000,000 |
| 1,000 | 1,000 | 1,000,000 | 1,000,000,000 |
| 10,000 | 10,000 | 100,000,000 | 1,000,000,000,000 |

复杂度降阶的价值不在小输入上少运行几次，而在于输入规模扩大后，运行量的增长速度发生了根本变化。

## 八、结论

Hash 查重的重要性可以概括为：

> 用额外空间保存历史信息，把“重新扫描寻找答案”变成“直接查询答案”。

但分析时不能只看到代码里用了 Hash，就直接宣布算法是 $O(n)$。必须继续检查：

- 一共有多少个状态或候选；
- 每个状态要执行多少工作；
- Hash 消掉了哪一个因子；
- 是否还有指针回退、重复枚举或其他嵌套扫描。

在本题中，Hash 有两次不同意义：

- `seen[]` 消掉窗口内部的线性查重，使 $O(n^3)$ 降为 $O(n^2)$；
- `last[]` 配合不回退的滑动窗口，消掉 `temp` 扫描，使 $O(n^2)$ 降为 $O(n)$。
