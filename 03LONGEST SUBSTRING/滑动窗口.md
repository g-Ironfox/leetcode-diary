# 滑动窗口：从区间枚举到状态复用

## 一、滑动窗口是什么

滑动窗口处理数组、字符串、时间序列等数据中的**连续区间**。使用闭区间表示窗口：

$$
[left,right]
$$

窗口长度为：

$$
right-left+1
$$

窗口算法的核心不是“使用两个指针”，而是：

> 相邻区间之间只相差少量元素，因此复用上一个区间的状态，不重新计算整个区间。

窗口状态可以是元素和、平均值、各元素出现次数、不同元素数量、最大值，或者某段时间内的事件统计。

按照边界移动方式，可以分成三类：

1. **定长滑窗**：窗口长度始终为 `k`；
2. **枚举左端点，向右扩展**：每个 `left` 都重新扩展 `right`；
3. **右侧扩张，左侧收缩**：`right` 不回退，`left` 按条件追赶。

这三类并不都保证 $O(n)$。关键要看元素是否被重复扫描，以及窗口状态能否增量维护。

## 二、分析窗口问题的四个问题

动手前先回答：

1. **窗口表示什么？**
2. **窗口状态是什么？**
3. **加入右侧元素和移除左侧元素时，状态如何更新？**
4. **什么时候记录答案？**

例如“最近 60 秒的请求数”：

- 窗口表示当前时刻之前 60 秒内的请求；
- 状态是窗口中的请求数量；
- 新请求从右侧进入，超过 60 秒的旧请求从左侧离开；
- 每次调整后得到当前请求数。

窗口在调整过程中始终维护的规则称为**不变量**。

## 三、定长滑窗

### 边界移动

定长窗口大小固定为 `k`：

```text
右侧加入一个元素
左侧移除一个元素
窗口整体向右移动一格
```

窗口依次为：

```text
[0, k - 1]
[1, k]
[2, k + 1]
...
```

### 适用问题

- 连续 `k` 天的最高平均销量；
- 任意 `k` 个连续采样点的最大能耗；
- 固定时间片内的移动平均值；
- 长度为 `k` 的所有区间统计。

常见题目信号是：“长度恰好为 `k`”“连续 `k` 个”“最近 `k` 次”。

### 示例：连续 k 天的最大销量

```c
#include <limits.h>

int maxSalesInKDays(const int *sales, int days, int k)
{
    if (sales == NULL || k <= 0 || k > days) {
        return 0;
    }

    int windowSum = 0;
    int maxSum = INT_MIN;

    for (int right = 0; right < days; right++) {
        windowSum += sales[right];

        if (right >= k) {
            windowSum -= sales[right - k];
        }

        if (right >= k - 1 && windowSum > maxSum) {
            maxSum = windowSum;
        }
    }

    return maxSum;
}
```

这里不必显式保存 `left`，因为：

$$
left=right-k+1
$$

不变量是：更新答案时，`windowSum` 恰好表示最近 `k` 天的销量之和。

每个元素进入窗口一次、离开窗口一次，所以时间复杂度为 $O(n)$，辅助空间复杂度为 $O(1)$。

如果需要维护固定窗口最大值，单纯加减无法完成，通常需要单调队列。此时时间复杂度仍可保持 $O(n)$，空间复杂度为 $O(k)$。

## 四、枚举左端点，向右扩展

### 边界移动

先固定一个 `left`，再让 `right` 从 `left` 开始向右扩展，直到条件不满足：

```text
for 每个 left:
    清空窗口状态

    for right 从 left 开始:
        尝试加入 right
        如果条件不满足:
            停止本轮
        更新答案
```

当 `left++` 时，`right` 会回到新的 `left`，所以一些元素会被重复访问。

### 它有什么用

这种方法最坏为 $O(n^2)$，但仍然有实际价值：

- 它通常是最直接、最容易验证的基准解；
- 数据规模较小时，实现简单可能更合适；
- 条件失败后永久失败时，可以提前结束内层循环；
- 可以生成正确答案，与优化算法进行随机对拍；
- 如果窗口最大长度存在很小的上限 `L`，复杂度是 $O(nL)$；
- 有些状态很难在移除左侧元素后维护，只能为每个起点重新计算。

### 示例：乘积不超过上限的最长区间

假设数组元素都是不小于 `1` 的正整数：

```c
int longestProductAtMostLimit(const int *numbers, int length, int limit)
{
    int maxLength = 0;

    for (int left = 0; left < length; left++) {
        long long product = 1;

        for (int right = left; right < length; right++) {
            product *= numbers[right];

            if (product > limit) {
                break;
            }

            int windowLength = right - left + 1;
            if (windowLength > maxLength) {
                maxLength = windowLength;
            }
        }
    }

    return maxLength;
}
```

继续向右扩展时，乘积不会减小，所以超过上限后可以停止当前轮。

最坏情况下，每个 `left` 都扫描到末尾：

$$
n+(n-1)+\cdots+1=\frac{n(n+1)}{2}
$$

因此时间复杂度为 $O(n^2)$。

判断它与线性滑窗的直接方法是：

> `left` 移动后，`right` 是否回退并重新扫描？

## 五、右侧扩张，左侧收缩

### 边界移动

这一类窗口的 `right` 始终向右移动，不会因为 `left` 改变而回退：

```text
right 加入新元素
根据条件移动 left
在合适的时机更新答案
```

它要求窗口条件随边界移动具有足够的**单调性**，从而确定应该移动哪一侧，并保证不会漏掉答案。

### 适用问题

- 总和不超过预算的最长连续消费区间；
- 总和至少达到目标的最短连续区间；
- 至多包含 `k` 种元素的最长区间；
- 覆盖所有目标元素的最短区间；
- 某个时间范围内的事件统计；
- 满足频次、容量或数量约束的连续区间。

这一类还要区分：**求最长合法窗口**和**求最短满足窗口**。

## 六、求最长合法窗口

求最长时，先扩张右侧；如果窗口不合法，就收缩左侧，直到窗口恢复合法，然后更新最大值：

```text
加入 right
while 窗口不合法:
    移除 left
    left++
更新最长答案
```

### 示例：总费用不超过预算的最长连续行程

假设每天费用都非负：

```c
int longestTripWithinBudget(const int *costs, int days, int budget)
{
    int left = 0;
    int windowCost = 0;
    int maxDays = 0;

    for (int right = 0; right < days; right++) {
        windowCost += costs[right];

        while (windowCost > budget && left <= right) {
            windowCost -= costs[left];
            left++;
        }

        int windowLength = right - left + 1;
        if (windowLength > maxDays) {
            maxDays = windowLength;
        }
    }

    return maxDays;
}
```

不变量是：更新答案时，窗口总费用不超过预算。答案必须放在 `while` 之后更新，因为此时窗口才重新合法。

## 七、求最短满足窗口

求最短时，右侧扩张直到满足条件；只要仍然满足，就不断记录答案并收缩左侧：

```text
加入 right
while 窗口满足条件:
    更新最短答案
    移除 left
    left++
```

### 示例：累计产量至少达到目标的最短天数

假设每天产量都为正数：

```c
#include <limits.h>

int minDaysToReachTarget(const int *output, int days, int target)
{
    int left = 0;
    int windowOutput = 0;
    int minDays = INT_MAX;

    for (int right = 0; right < days; right++) {
        windowOutput += output[right];

        while (windowOutput >= target) {
            int windowLength = right - left + 1;
            if (windowLength < minDays) {
                minDays = windowLength;
            }

            windowOutput -= output[left];
            left++;
        }
    }

    return minDays == INT_MAX ? 0 : minDays;
}
```

答案必须在 `while` 内、移除左侧元素之前更新，否则可能错过当前满足条件的最短窗口。

## 八、窗口状态不只是一笔总和

同一套边界移动方法可以搭配不同的数据结构：

| 需要维护的信息 | 常见状态 |
| --- | --- |
| 区间总和 | 一个累加变量 |
| 各元素出现次数 | 计数数组或哈希表 |
| 不同元素数量 | 哈希表加计数器 |
| 固定窗口最大值 | 单调队列 |
| 是否覆盖目标集合 | 频次表加已满足种类数 |
| 时间范围内事件 | 队列或双端队列 |

所以滑动窗口是一种**区间移动策略**，不是限定使用某一种数据结构。

能否高效滑动，取决于窗口状态是否支持：

```text
add(rightElement)
remove(leftElement)
```

如果加入和删除都能在 $O(1)$ 或较低复杂度内完成，窗口通常就能高效维护。

## 九、为什么嵌套 while 仍可能是 O(n)

可变长窗口中常出现：

```c
for (int right = 0; right < length; right++) {
    while (condition) {
        left++;
    }
}
```

虽然有循环嵌套，但整个算法中：

- `right` 最多移动 `n` 次；
- `left` 最多移动 `n` 次；
- 两者都不回退。

总移动次数不超过 $2n$，因此边界移动的总复杂度为 $O(n)$。这种分析称为**均摊分析**。

如果每次维护窗口状态还需要 $O(\log n)$，总复杂度可能是 $O(n\log n)$。所以“双指针不回退”不代表整个算法必然是 $O(n)$。

## 十、滑窗成立需要单调性

以“区间和不超过预算”为例。如果所有元素非负：

- 右侧加入元素，区间和只会增大或不变；
- 左侧移除元素，区间和只会减小或不变。

因此超出预算时，移动 `left` 是明确且安全的。

如果允许负数：

- 右侧加入负数可能让区间和减小；
- 左侧移除负数可能让区间和增大。

此时“超出就收缩、未超出就扩张”的方向不再可靠，普通滑窗可能漏解。可能需要前缀和、哈希表、单调队列、二分查找或有序结构。

所以“连续子数组”只是考虑滑窗的信号，不是使用滑窗的充分条件。

## 十一、三类窗口对比

| 类型 | `left` 如何移动 | `right` 是否回退 | 常见复杂度 | 主要用途 |
| --- | --- | --- | --- | --- |
| 定长滑窗 | 每轮同步右移 | 不回退 | $O(n)$ | 固定长度区间统计 |
| 枚举左端点，向右扩展 | 外层每次右移一格 | 回到新的 `left` | 最坏 $O(n^2)$ | 基准解、小规模问题、难以删除状态的问题 |
| 右侧扩张，左侧收缩 | 根据条件右移若干格 | 不回退 | 常见为 $O(n)$ | 最长合法区间、最短满足区间 |

三类方法可以统一成：

```text
1. 确定窗口边界的移动规则
2. 定义并增量维护窗口状态
3. 维护窗口不变量
4. 在正确时机更新答案
```

## 十二、从朴素扩展优化到线性滑窗

拿到“枚举 `left`，向右扩展”的 $O(n^2)$ 解法后，可以依次追问：

1. `left++` 后，上一个窗口中的哪些元素仍然有效？
2. 能否只删除旧的 `left`，而不是清空全部状态？
3. `right` 能否停在原位继续向右，而不是退回？
4. 窗口失效后，移动 `left` 是否一定能让它恢复？
5. 窗口条件是否具有单调性？

如果答案都是肯定的，就可能把 $O(n^2)$ 优化为 $O(n)$。

最值得迁移到其他问题的不是某段模板，而是：

> 发现相邻区间之间可以复用什么，以及如何删除离开窗口的元素所产生的影响。

## 十三、检查清单

1. 处理的是不是连续区间？
2. 窗口采用 `[left, right]` 还是 `[left, right)`？
3. 窗口状态是什么？
4. 加入右侧元素时怎样更新状态？
5. 移除左侧元素时怎样恢复状态？
6. 合法条件或满足条件是什么？
7. 求最长还是求最短？答案应该在哪里更新？
8. 两个边界是否回退？复杂度如何证明？
9. 条件是否具有支持窗口移动的单调性？
10. 固定长度、空输入、目标不可达等边界情况是否处理？

一句话概括：

> 让连续区间有规律地移动，并复用相邻区间之间的大部分计算结果。
