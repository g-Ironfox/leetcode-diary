# Two Sum 算法对比

> 详细原理解析见 [SUM TWO.md](./SUM%20TWO.md)

---

## 理论复杂度

| 文件 | 时间 | 额外空间 |
|---|---|---|
| `twoSum_bruteforce.c` | $O(n^2)$ | $O(1)$ |
| `twoSum_binary_search.c` | $O(n \log n)$ | $O(n)$ |
| `twoSum_hashmap.c`（堆） | $O(n)$ | $O(n)$ |
| `twoSum_hashmap_static.c`（栈） | $O(n)$ | $O(n)$ |

> 栈版 `HASH_CAPACITY = 20001` 来源于 `2×10⁴ + 1`，即与最大输入规模 $n_{\max}$ 成正比。
> 它把按实际 $n$ 分配改为按题目上限预留，并未消除 $O(n)$ 的哈希表存储。
> 实际占用 ~160 KB。

---

## LeetCode 实测（n ≤ 10⁴）

| 方案 | 耗时 | 击败 | 内存 | 击败 |
|---|---|---|---|---|
| 暴力枚举 | 117 ms | 20% | 9.38 MB | 29% |
| 排序+二分 | 0 ms | 100% | 9.85 MB | 16% |
| HashMap（堆） | 0 ms | 100% | 10.20 MB | 13% |
| HashMap（栈） | 0 ms | 100% | 9.41 MB | 24% |

> 内存占用都好高,我感觉是C的问题,因为leetcode可以用很多种程序语言

### 内存排名

```
暴力      9.38 MB  ← 基线
静态Hash  9.41 MB  ← +0.03 MB
二分      9.85 MB  ← +0.47 MB
堆Hash   10.20 MB  ← +0.82 MB
```

### 要点

- $O(n^2)$ 和 $O(n \log n)$ 在 $n=10^4$ 下已有 117ms 的可见差距。
- 三种 $O(n)$ / $O(n \log n)$ 方案全部 0ms，LeetCode 计时器无法区分。
- 静态 Hash 最均衡：0ms 且内存仅比暴力多 0.03 MB。
- 堆 Hash 内存最大：动态分配 `2n+1` 槽位 + 堆管理开销。
