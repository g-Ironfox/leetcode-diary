# SUM TWO Diary

这是一次 Two Sum 做题经历留下的学习日记。

## 由GPT大大为我代笔,我只是零零碎碎留了不少的片段

它不是一篇从标准答案倒推出来的教程，也不试图把每个概念讲成完整的教材章节。这里保留了当时的误解、联想、绕路和情绪：从一道本来很简单的题出发，先想到排序，再想到 Hash，最后一路追问到存储、寻址和程序的状态转移。

内容后来越写越远，因此拆成了五篇：

| 文档 | 内容 | 适合怎么读 |
|---|---|---|
| [Two Sum 解题笔记](./SUM%20TWO.md) | 题目复盘、暴力枚举、排序与双指针、HashMap 解法、复杂度对比 | 建议从这里开始，理解整组笔记是怎么长出来的 |
| [Hash 学习笔记](./Hash.md) | HashSet、HashMap、碰撞、扩容、状态 Hash、数据库索引 | 想继续追问“空间换时间到底存了什么”时阅读 |
| [C 语言：静态、自动与动态内存](./C语言静态与动态内存.md) | 栈、堆、静态存储期、内存计算，以及两个 Two Sum 版本的对比 | 想弄清固定数组和 `malloc` 在通用 C 程序中究竟差在哪里时阅读 |
| [嵌入式内存管理](./嵌入式内存管理.md) | MCU/MPU 内存规划、实时确定性、堆碎片、动态链表和内存池 | 想理解嵌入式系统为何强调静态分配，以及如何替代通用堆时阅读 |
| [计算机原理：存储、寻址与状态转移](./计算机原理.md) | 数据结构的存储方式、位置标识、寄存器、控制流和计算模型 | 想沿着“数据究竟放在哪里、程序怎样继续执行”往下读时阅读 |

## 阅读方式

推荐顺序是：

```text
Two Sum
→ Hash
→ C 语言静态与动态内存
→ 嵌入式内存管理
→ 计算机原理
```

不过它们也可以单独阅读。只想看解法，到 Two Sum 的“解法对比”为止即可；只想复习 Hash 或计算机原理，可以直接进入对应文档。

## 关于这份日记

这组文档记录的是一个具体时刻的理解，而不是永远正确、永远完整的定稿。后续学习中发现概念不准确、论证不充分或有了新的联想，我会继续修改。

比起只留下几行标准代码，我更想保留的是：当时为什么会想错、怎样从旧经验迁移、在哪个概念上卡住，以及一个简单问题如何牵出更大的知识网络。
